## Name | Where | Explain with my words
| :--- | :--- | :--- |
| **`__construct / new PDO`** | In class `Database` | This is literally the door we knock on to get into the database. It takes the server address, the database name, and the password, and it gives us back a connection handle ready so we can send our commands to it. |
| **`prepare()`** | In classes from `repositories` (Book, Card, Loan, and Member) when Add, Update, and Search | In our smart approach to protect against hackers (SQL Injection), instead of directly inserting user input into the query, we prepare the query as a blank template and leave placeholders (like `:name`) to safely fill in later. |
| **`execute()`** | In classes from `repositories` after `prepare()` | Here we tell PHP: Go ahead, these are the real data entered by the user, put them in the empty spots of the template we prepared, and execute the command immediately in the database. |
| **`query()`** | In class `ReportRepository` | We use this when our query is "clean" and doesn't contain any external input from the user (like fetching all books). In this case, we execute the command directly without preparing it because there is no risk of SQL injection. |
| **`fetch()`** | In methods like `findById`, `findByCardNumber` | It pulls just one line from the result. So if I'm looking for a book by a certain number, the function brings me the data for that book alone and puts it in an array ready to use. |
| **`fetchAll()`** | Inside the report functions in `ReportRepository` | Unlike the previous one, it pulls in all the rows that came from the query and returns them to me as one big array. Super useful when we want to print a long list, like a list of overdue books or all the members. |
| **`fetchColumn()`** | In class `LoanRepository` | Used when my query is going to return just a single value (like a number or a single date). Instead of grabbing a whole row with columns, it picks up that value immediately and gives it back to me as a direct number or text. |
| **`lastInsertId()`** | In function `saveAndGetId` from `MemberRepository` | When we add a new member, the database automatically gives them an ID (Auto Increment). This function's job is to grab that new ID and return it to us immediately so we can use it and link it to the library card we're going to issue. |
| **`PDO::FETCH_ASSOC`** | In functions like `fetch` and `fetchAll` | This parameter tells PHP: When you fetch data from the database, return it as an array whose keys are the column names (like `['title']` or `['name']`). If we don’t set it, PHP will return the data twice (once with names, once with numbers), which wastes memory. |
| **`PDO::ATTR_ERRMODE => PDO::ERRMODE_EXCEPTION`**| In class `Database` | This option configures how PDO handles errors. Instead of hiding a database error (like a wrong table name) or staying silent, it forces PDO to throw an Exception, stop working, and tell you exactly where the error is. This allows us to catch errors safely using `try-catch` blocks. |
| **`PDO::ATTR_DEFAULT_FETCH_MODE`**| In class `Database` | This line tells PDO: From now on, consider `FETCH_ASSOC` as your default setup, and there's no need for me to remind you about it in every fetch function. |
| **`PDO::ATTR_EMULATE_PREPARES`**| In class `Database` | Sometimes PHP tries to 'emulate' Prepared Statements by itself without sending them to the actual MySQL engine. When we set this option to false, we're basically telling PHP: don't overthink it, just send the empty query directly to MySQL and let the database engine fill in the data. This gives you 100% protection from SQL injection. |
